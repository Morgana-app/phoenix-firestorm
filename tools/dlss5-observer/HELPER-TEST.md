Use **`build-vc/Launch-HelperNeural.cmd`** for this experiment. The normal `Launch-EarlyNeural.cmd` remains the working fixed-size baseline.

Log in, wait 15 seconds, resize smaller, wait 15 seconds, restore the original size, wait 30 seconds, then quit normally. Check that the neural appearance returns and HUD/UI stays sharp at each settled size. Leave the launcher console open so it can restore the baseline.

The launcher temporarily replaces the in-process Feeder with the local fsresize1 x64 helper client based on official v1.19.0 and installs our resize-capable v0.8 observer. It moves the consumer out of the viewer's add-on directory: only the separate, unchanged official `host64/dlss5-feed-host64.exe` loads it. The helper runs hidden, synchronously returns the current processed frame, uses the existing style-0/native-resolution settings and has its global toggle/screenshot keys disabled. A temporary Windows high-performance GPU preference selects NVIDIA for this helper executable; its previous value is restored afterward. The original Firestorm installation is untouched.

Our controller still runs Kernel → Feed before UI/HUD. This changes Feeder's transport and consumer lifecycle; it does not establish that resizing is fixed. Upstream's 64-bit OpenGL helper route is compiled but not game-verified. The standalone helper check on this laptop passed 300/300 DLAA evaluates, with actual feature-18 creation and neural evaluation both before and after its same-size warm-up recreation. That is compatibility evidence, not a Firestorm resize test or a visual-quality/performance benchmark.

`Run-HelperNeural.ps1 -PrepareOnly` rehearses file swapping, preset preparation and exact restoration without starting Firestorm or changing the GPU preference. This rehearsal passed, and all seven working component hashes still match the baseline afterward.

Evidence is saved under `build-vc/scene-signal-controls/HelperNeural-*/`: the nested EarlyNeural folder contains viewer/Feeder/controller logs; `host64/` contains the final helper's logs and `host64/sessions/host-*-pid-*/` retains retired helpers' logs before replacements overwrite them. `helper-build.json` identifies the locally compiled candidate and input hashes. Success requires distinct helper PIDs on builds after resizing, actual feature-18 evaluations at all settled sizes, no duplicate Feed processing, sharp UI, normal viewer exit and successful baseline restoration. Controller composition counts alone are insufficient. The separate helper's presents are its own window, so its evaluation/present ratio cannot be interpreted as the viewer's frame ratio.

Build with `Build-FeederHelper.ps1` after placing the official v1.19.0 source and required Vulkan headers in `.deps/lifecycle/` as the script expects. It verifies the pristine helper source hash, creates a build copy, applies the local include/hooks, invokes upstream's x64 helper build and records hashes. The Vulkan headers only satisfy compilation of upstream's existing transport; Firestorm uses OpenGL. The local behavior requires `FS_FEEDER_RESTART_ON_RESIZE=1`, set only on the helper-test viewer child process. Other modes explicitly remove that variable. The client has not been patched to expose official NVIDIA SDK integration.

If the launcher is interrupted while Firestorm is still open, it leaves originals in `build-vc/scene-signal-controls/held-helper-session/`. Close Firestorm first. Restore each original file listed in `original-hashes.json` from that folder to `build-vc/newview/Release/`, verify hashes, and preserve the evidence. The existing lifecycle controller may also leave `held-copy-settings` and `running.lock`; recover its settings before removing its lock. Do not start another launcher over an interrupted session.

This is a local investigation launcher; the package installer does not install it. Its source may be included with the other development scripts. Local third-party copies remain excluded from Git and packages.
